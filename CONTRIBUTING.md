# Contributing to TrackX

Thank you for your interest in contributing to TrackX! Please follow these guidelines to keep our codebase clean and maintainable.

## Code Style & Formatting

- Follow standard Dart style conventions.
- Format your changes using `dart format .` before pushing.
- Ensure `flutter analyze` reports zero errors or warnings.

## Testing Requirements

- All business logic updates must be covered by unit tests.
- UI changes should include relevant widget tests.
- Run the full test suite using `flutter test` before creating a pull request.

## Branching & Pull Requests

1. Fork the repository and create your feature branch: `git checkout -b feature/amazing-feature`.
2. Commit your changes: `git commit -m 'feat: add amazing feature'`.
3. Push to the branch: `git push origin feature/amazing-feature`.
4. Open a Pull Request detailing the changes, screenshots of UI updates, and test validation.
